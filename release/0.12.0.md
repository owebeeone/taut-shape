## Validation

- Compiler strict candidate gate: 2,645 native Windows tests plus four POSIX
  tests over the same candidate, with an exact 2,649-case union and no skips
  or omissions. The eight duplicate parity gate wrappers are accounted for
  separately; all 16 mandatory parity variants passed all 134 rows each.
  Metadata, standalone foundation packaging, distributions and smoke checks passed.
- Compiler publication CI: Python 3.10, 3.11, 3.12, 3.13 and 3.15 passed. These
  hosted Linux runs retain platform/optional-feature skips; they are additional
  coverage, not a replacement for the no-skip Windows/POSIX qualification.
- Rust shape: 109 tests, warnings-as-errors Clippy, no-default-features build
  and locked registry-only packaging passed in Gearu and publication CI.
- TypeScript shape: 316 tests, typecheck, frozen install and packaging passed.
- Python shape: 197 tests against published `taut-proto`, distribution builds
  and publication smoke checks passed. All five Python publication jobs passed.
- Live cross-language matrix, harness regressions and compatibility regression
  tests: 328 passed after the foundation registry lock was refreshed.

## Finalization hold: Glial's separate Glade dependency

Glial's isolated `check:release` and its
[consumer CI check](https://github.com/owebeeone/glial-runtime/actions/runs/43949087605)
fail because `@owebeeone/glade-decl 0.1.1` does not export `./assistance`.
Glial already imports that API; the Glade declarations source checkout has it,
but its immutable published 0.1.1 artifact does not. The Taut Shape 0.12 registry
dependency itself resolves successfully. Do not replace this check with a local
Glade package or describe it as passed.

Resolving that issue needs a separate Glade declarations release and an updated
Glial dependency pin/registry lock, followed by the complete isolated consumer
check. Ownership/authorization for that additional release remains open.
The read-only Gearu minor-release plan selects `glade-decl-ts 0.2.0`; no such
release or source edit was performed as part of the Taut train.

The compatibility manifest deliberately remains `candidate`, and the contract's
`v0.12.0` tag/GitHub Release have not been created. On clean release inputs,
`check_compatibility.py --release --contract-version 0.12.0` currently rejects
only that candidate status. This is an intentional hold, not a passing final gate.
After the consumer dependency is resolved, rerun the consumer and compatibility
checks, mark the manifest released, commit/push through GWZ, then release the
contract with Gearu and capture the final workspace checkpoint.
